# 选题：让机器认出你的饮料

## 一、课程概述

### 课程名称

让机器认出你的饮料：YOLO 目标检测入门与误检改进

### 选题背景

目标检测是机器人获取环境信息的一种常见方式。摄像头拍到的图像经过模型处理后，可以得到目标的类别、位置和置信度，这些结果还可以继续提供给机械臂抓取、移动机器人导航或安全监控等后续模块。

饮料容易准备实物（其实是想要公费喝饮料😋），检测结果也很直观，适合作为初学者完成第一次目标检测实践。因此，本课程让参与者训练一个能够识别可乐、雪碧和芬达的模型，再通过现场制造遮挡、暗光和复杂背景等情况，引导大家分析模型为什么会出错，以及怎样通过补充数据或调整参数进行改进。

### 课程规模与形式

- 预计参与人数：约 60 人；
- 分组方式：4 人一组，共 15 组；
- 课程安排：1 个课时，共 90 分钟；
- 教学形式：教师讲解、分组实践、现场挑战和结果讨论相结合；
- 授课人：1 名主讲人和 4 名助教，每名助教负责 3 至 4 组。

## 二、面向对象与所需基础

课程面向对机器人视觉或人工智能感兴趣的同学，默认参与者没有深度学习基础。

参与者不需要预先理解神经网络的数学原理，会进行基本的文件操作，并能根据说明运行 Python 程序即可。课程开始前发放经过实测的环境说明和依赖版本，参与者只需按说明完成 Python 与 Ultralytics 环境准备，并运行测试程序确认环境可用。

## 三、学习目标

完成课程后，参与者应当能够：

1. 理解目标检测要解决什么问题，以及它在机器人视觉中的基本作用；
2. 读懂 YOLO 检测结果中的类别、检测框和置信度；
3. 理解模型训练中参数、Loss、梯度下降和反向传播的基本直觉，知道“训练”本质上是在不断调整参数以降低 Loss；
4. 理解训练集、验证集、预训练模型和微调的作用；
5. 使用预训练权重完成一次小规模模型微调，并使用训练后的模型检测饮料；
6. 区分模型自动学习的参数与人工设置的训练配置，例如 learning rate、epochs、batch size；
7. 从失败图片中分析光照、遮挡、背景、视角和数据覆盖等可能原因，并提出可执行的改进方案。

本课程不要求参与者推导 YOLO 的完整网络结构、真实损失函数或矩阵形式的反向传播，也不要求现场完成图片标注。

理论部分只讲到能够理解训练过程所需的最小数学直觉：参数如何影响输出、Loss 如何衡量当前预测与目标之间的差异、梯度如何提供局部调整方向，以及反向传播如何高效计算各参数的梯度。

课程重点是让初学者体验“预测—训练—测试—制造失败—分析失败—提出改进”的完整过程。

## 四、课程内容与课时安排

### 课前准备

授课团队提前完成以下工作：

1. 发放课程文件夹，内含训练集、训练程序、检测程序和环境测试程序；
2. 提醒参与者提前按照经过实测的环境说明安装 Python 与 Ultralytics，并运行测试程序；
3. 在实际使用的课程文件和依赖版本上完成测试，并提供统一的一键环境测试脚本；
4. 准备一个训练完成的备用模型，环境安装失败或训练过慢的组可以直接进入检测环节。

课堂训练的目标是让参与者理解并亲手启动一次训练流程，而不是要求每组必须在现场训练出可用于后续实验的模型。任何训练失败、安装异常或训练时间超过预期的小组均可直接切换统一备用模型继续后续实验。

### 课堂安排

| 时间 | 教学内容 | 参与者活动 |
|---|---|---|
| 0–8 分钟 | 现场展示饮料检测，并故意制造一次遮挡或暗光下的识别失败，提出“模型为什么会认错？” | 观察正常与失败结果，尝试猜测原因 |
| 8–15 分钟 | 介绍目标检测输出：类别、检测框、置信度，以及它与简单图像分类的区别 | 读懂一张 YOLO 检测结果 |
| 15–30 分钟 | 用可视化讲解模型如何学习：参数、Loss、梯度下降、学习率和反向传播的基本直觉 | 根据动画回答“参数应往哪边调”“学习率过大或过小会怎样”等问题 |
| 30–38 分钟 | 介绍预训练、微调、训练集、验证集，以及 `data.yaml` 与几个关键训练配置 | 查看课程提供的数据集结构与训练脚本 |
| 38–48 分钟 | 各组启动短时训练；训练期间解释输出目录、loss 曲线和 `best.pt` | 运行训练并观察输出；未完成者直接切换备用模型 |
| 48–65 分钟 | 基础饮料识别实验 | 检测可乐、雪碧和芬达，确认模型在正常条件下的表现 |
| 65–78 分钟 | 误检挑战 | 尝试遮挡、暗光、侧面、远距离、多目标、复杂背景等条件 |
| 78–86 分钟 | 失败样本分析 | 每组选择一张失败或不稳定结果，讨论可能原因与改进方向 |
| 86–90 分钟 | 分享与总结 | 2–3 组分享一个失败案例；教师总结数据、模型、参数与机器人应用之间的关系 |

课堂使用轻量模型进行微调，计划采用 YOLO11n 或同等级模型。训练集、图片标注和配置文件由授课团队提前准备，参与者无需现场制作数据集。训练轮数和图片尺寸在课前通过普通笔记本实测后确定。超过预定时间仍未完成训练的组直接使用备用模型，不影响后面的饮料识别实验。

理论讲解部分不追求完整数学推导，而是通过动画建立直觉：

- 参数决定模型的输出；
- Loss 用来衡量当前预测与目标之间的差异；
- 梯度描述参数局部变化对 Loss 的影响；
- 学习率决定每次更新的步长；
- 反向传播负责计算梯度，优化器依据梯度更新参数。

只展示一条基础梯度下降公式作为核心数学内容：

\[
w_{\text{new}} = w_{\text{old}} - \eta \frac{\partial L}{\partial w}
\]

链式法则只用于说明“早期参数对最终 Loss 的影响可以沿计算路径逐层传递”，不要求参与者现场计算。

### 与授课型幻灯片 Demo 的对应关系

本次 10 分钟授课型 Demo 选取完整课程中“模型如何学习”这一段进行展示。

Demo 重点讲解：

`预测 → Loss → 梯度 → 反向传播 → 参数更新`

并通过简单PPT动画解释参数、学习率和链式法则的直觉。

## 五、实践活动设计

### 饮料分配

每组准备 4 瓶饮料，其中包括 1 瓶可乐、1 瓶雪碧、1 瓶芬达和 1 瓶随机重复饮料。15 组共需 60 瓶。重复饮料可以用于同类不同包装、不同距离或多目标检测实验。

每组自行分工完成程序运行、饮料拍摄和结果记录。主讲人在实验过程中提醒成员轮流参与，避免只有一名熟悉电脑的成员完成全部操作。

### 检测程序的操作方式

为了把课堂时间留给模型理解与实验分析，检测程序应尽量减少文件路径、命令行和手机传图带来的额外操作。

优先方案是使用电脑摄像头进行实时检测；如果设备条件不适合实时摄像头，则提供一个固定的 `test_images/` 文件夹，参与者只需将测试图片放入该目录并运行统一检测脚本。

### 误检挑战

误检挑战不是单纯“想办法把模型骗错”，而是用于验证前半节课学到的一个核心问题：模型在训练数据中学到了哪些稳定特征，又在哪些没有覆盖的场景中容易失效？

各组从下列条件中至少选择三种进行测试：

- 遮挡部分瓶身或商标；
- 从饮料罐顶部倾斜拍摄；
- 改变拍摄距离和目标大小；
- 在较暗或过亮的环境中拍摄；
- 将多瓶饮料放入同一画面；
- 使用与包装颜色相近的物体或复杂背景进行干扰；
- 使用相似颜色的瓶子检测。

每组提交一张成功检测结果和一张失败或表现不稳定的结果，并尝试回答：

1. 这次失败最可能与哪些因素有关？
2. 这个判断有什么证据？
3. 如果继续改进，你会优先补数据、检查标注、调整训练配置还是修改推理阈值？为什么？

### 与机器人应用的联系

课程最后说明，模型提供的类别和检测框只是感知结果。机器人还需要把检测框转换为目标位置，并结合深度、相机标定、目标跟踪和控制模块，才能完成抓取、导航或预警任务。课程不在现场实现完整机器人系统，但为后续视觉定位和机器人控制内训建立接口概念。

## 七、课程成果

每组完成以下成果即可视为完成实践：

1. 能解释一次完整训练流程中“预测—Loss—梯度—参数更新”的基本关系；
2. 成功启动一次短时训练，或在训练受限时使用备用模型完成后续实验；
3. 保存至少一张正常条件下的检测结果；
4. 提交一张失败或表现不稳定的测试结果；
5. 对失败原因提出一个有依据的假设，并给出一种可执行的改进方法。

## 八、可能遇到的问题与解决办法

### 环境安装失败

课前发放一页安装说明和环境测试程序。课堂上如仍有小组无法运行训练程序，直接使用备用模型完成饮料识别和误检分析。

### 不同电脑训练时间差异较大

采用轻量模型、小规模数据集和短时微调。训练期间穿插指标讲解，不安排纯等待时间。课前在无独立显卡和有独立显卡的电脑上分别实测，并据此确定训练轮数。超过预定时间仍未结束的组直接切换到备用模型。

课程不把“现场训练结束”设为后续实验的必经条件，因此不会因为个别电脑性能较弱导致整个小组停在等待阶段。

### 60 人同时操作导致答疑压力过大

主讲人将操作步骤投影展示，助教优先处理影响全组继续学习的问题。每组只使用一台主训练电脑，将需要排查的环境数量控制在 15 台。

### 模型效果过好或过差，互动价值不足

训练集应覆盖基本场景，但故意不包含所有拍摄条件，使普通测试能够成功，遮挡、暗光和复杂背景仍可能暴露问题。课前使用保留测试集检查难度，并准备若干稳定的成功与失败案例。

### 理论部分对初学者过难

理论部分只围绕一个问题展开：“模型怎样知道参数应该往哪里改？”

使用可视化和具体饮料例子讲解参数、Loss、梯度下降与反向传播，只保留一条基础更新公式，不要求参与者进行复杂求导。

每个抽象概念讲完后立即用一个简单判断问题验收，例如：

- Loss 变大意味着当前预测更好吗？
- 学习率过大会出现什么直观问题？
- 反向传播负责计算梯度还是直接修改参数？

如果现场反馈不佳，可一笔带过数学公式，只保留路径影响的直觉解释，不影响后续实践。

### 拍照、传图和文件路径占用过多时间

优先使用摄像头实时检测；如必须使用静态图片，则统一使用固定测试目录和一键检测脚本。

课程不把文件管理和命令行操作作为本节内训的学习目标，避免低价值操作挤占模型分析时间。

### 饮料类别与颜色形成过强对应

课程中主动讨论模型究竟学习了品牌、文字、瓶形还是包装颜色。可以使用相近颜色的非饮料物体、不同包装版本或遮挡商标的图片测试模型，帮助参与者理解数据偏差。
