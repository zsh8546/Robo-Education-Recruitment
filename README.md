## Git 与 GitHub 使用说明

### 1. 本次任务中使用了哪些 Git 或 GitHub 功能？

本次任务中，我主要使用了以下 Git 与 GitHub 功能：

- 在 GitHub 上创建远程仓库；
- 使用 `git clone` 将仓库克隆到本地；
- 使用 `git status` 查看工作区和暂存区状态；
- 使用 `git add` 将需要提交的文件加入暂存区；
- 使用 `git commit` 保存具有实际意义的版本记录；
- 使用 `git push` 将本地提交同步到 GitHub；
- 使用 `git switch -c` 创建独立分支完成补充修改；
- 使用 GitHub Pull Request 检查分支改动并合并回 `main`。

在操作过程中，我也逐渐理解了工作区、暂存区、本地仓库和远程仓库之间的区别，而不只是完成文件上传。

### 2. 操作过程中遇到了哪些问题？你是如何解决的？

第一次执行 `git commit` 时，Git 提示 `Author identity unknown`，原因是当前电脑还没有配置提交者身份。之后使用 `git config user.name` 和 `git config user.email` 为当前仓库配置用户名和邮箱，再次提交后成功完成 commit。

第一次 `git add` Markdown 文件时，还遇到了 `LF will be replaced by CRLF` 的提示。查明后了解到这是 Windows 与 Linux/macOS 常用换行符不同造成的提示，对于本次 Markdown 文件不会影响正常使用，因此暂未额外修改。

由于最开始克隆的是一个空仓库，本地第一次 commit 后，`git status` 还提示远程 `origin/main` 尚不存在。完成第一次 `git push -u origin main` 后，本地 `main` 与远程 `main` 建立了跟踪关系，之后即可直接使用 `git push` 同步提交。

### 3. 如果以后需要多名教学部成员共同维护这个仓库，你认为应当如何组织文件与修改流程？

我认为首先应保持清晰、稳定的目录结构，使不同类型的资料分别存放，例如将课程方案、幻灯片和图片素材放在不同目录中，并通过 README 说明各目录用途和当前维护状态。

在多人协作时，可以让每个人针对自己的修改创建独立分支，在分支上完成修改和测试后，再通过 Pull Request 合并到主分支。这样既可以避免多人直接修改 `main` 导致冲突，也方便其他成员在合并前检查修改内容。本次任务中我也实际尝试了一次上述流程：由于首次提交时遗漏了幻灯片导出的 PDF，因此没有直接继续修改 `main`，而是新建独立分支补充 PDF 并同步修改 README，随后通过 Pull Request 检查改动并合并回主分支。

提交时应尽量保持每个 commit 只对应一个明确的修改目的，并写清楚 commit message。开始修改前先同步最新版本，避免在过旧的版本上继续工作；如果出现冲突，应先确认双方修改意图，再决定如何合并，而不是直接覆盖其中一方的内容。
